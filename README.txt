# BJTU Life Simulator 北交人生

软件开发与测试综合实践网页 MVP。程序版本 0.5.0，规则版本 3，存档格式版本 1。沿用现有 HTML、CSS、JavaScript 和校园地图，无需业务服务器或账号。

本次主分支整合内容、合并冲突处理、缺陷修复及验证结果见 [主分支合并与问题修复说明](docs/主分支合并与问题修复说明-20261021.md)。

## 运行

在本目录启动静态 HTTP 服务，例如：

    python -m http.server 8765

然后打开 http://127.0.0.1:8765/ 。部署时将页面、脚本和 assets 一起发布到固定站点。

双击 index.html 可试用界面；正式存档和验收使用 HTTP/HTTPS。不同协议、域名、端口、浏览器各自拥有独立存档。

## 本轮确定的玩法

- 保留成绩、社交、体能、心情、钱包五项核心属性。时间与精力是行动资源。
- 学习只有一项“本学期学习进度”，内部字段 preparation。课程、自学、补习和项目投入都使用它，不另设平时分、学识或专业能力。
- 期末成绩固定为 Math.round(40 + preparation * 0.6)。下学期学习进度清零，八学期成绩记录保留。
- 初始时间 12、精力 80、钱包 1000、社交 20、体能 50、心情 70；每学期生活支出 300，资金不足由援助补足。
- 保留旧版休息收益：精力已满但心情未满时仍可改善心情，两者都满才禁用。
- 十一个地图入口均可行动：思源楼（课程）、图书馆（自习与深造）、逸夫楼（项目）、学生活动中心（社团）、宿舍（休息交流）、南门（勤工与求职）、操场（锻炼）、银杏大道（散步）、校医院（体检与看病）、红果园宾馆（校友接待志愿）、天佑会堂（看演出）。
- 填写昵称后，随机分配简化学院类别和专业方向。信息类自学减少精力消耗、工程类项目有学习回报加成、经管类社团有社交回报加成。背景不锁定路线。
- 原“校外兼职”改为虚构的校内勤工助学；实习通过校内申请与经历进度模拟。

## 事件与方向

项目、社团、实习各有申请、投入、成果确认三个主要节点。接受邀请后投入两次；项目和社团须进入加入之后的学期再确认，实习可在两次投入后确认。未完成投入到期时延期并保留进度，最后学期仍未完成则记为未完成。成果确认可完成、延期或免费放弃。

项目第 2～6 学期开放申请，要求本学期学习进度 40。社团第 1～6 学期的秋季开放。实习第 5～7 学期开放，要求已结算平均成绩 60。大三起开放深造和求职准备，准备进度跨学期保留。

保留室友关心与体测体验。每学期第一次满足场景条件且没有其他待处理事件的行动，有 35% 概率从对应随机日常池抽中一个事件；每学期只抽取一次。随机过程统一使用带种子的 mulberry32，日常行动与部分事件的数值回报根据玩家投入和现场发挥结算；期末成绩仍由实际累积的学习进度计算。

事件按学期进度和行动场景调度：

- 固定事件：大一军训在开学早期、至少完成两次行动后触发，接受后连续完成训练与汇演，期间不穿插其他行动或事件；大二上转专业通知、大三下深造宣讲在学期中触发；大四毕业季在最后一学期末触发。上学期课程未达标时，开学提示补考。各节点每学期至多一次。
- 多阶段事件链：歌手大赛在秋季中段报名，后续复赛与决赛等待下一次行动；春运在秋季末安排往返车次，下一春季初返校，确认上车后再行动才可分享特产；学科竞赛在大三上中段招募。后续节点要求明确接受前置选项，拒绝或中断不会继续。一次普通行动最多开启一个校园事件，处理选项不会继续连弹可选校园事件；室友关心及主动申请的项目等必要提示仍可排队。
- 随机日常池：十六种事件按场景筛选，自习对应图书馆、锻炼对应球场、演出对应会堂、校友志愿对应宾馆。北京初雪只在秋季末散步时出现，快递爆仓只在秋季后段宿舍交流时出现，毕业大戏只在春季末看演出时出现。每学期一次35%抽取，使用同一随机值选取池中事件。
- 新增经历类型：军训（military）、歌手大赛（singer）、返乡（trip）、竞赛（contest），每局至多记录一次，并纳入存档校验白名单。

地图显示“学期初／中／末”：每学期12点时间，已用0～4点为初、5～8点为中、9～12点为末；这是进度提示，不是具体周历。详细窗口在 config.js 的 CAMPUS_SCHEDULE 与 RANDOM_CONTEXTS 中配置。旧档当前已展示的事件继续处理，尚未展示的错误校园积压会在处理当前事件后清理并按新窗口重新判断；已完成记录保留。

| 方向 | 条件 |
| --- | --- |
| 普通毕业 | 平均成绩至少 60，且至少六学期达标 |
| 继续深造 | 基础毕业条件、平均至少 80、完成项目、深造准备至少 60 |
| 进入就业 | 基础毕业条件、完成实习、求职准备至少 60 |
| 暂未达到毕业条件 | 未满足基础毕业条件，仍展示记录并结束 |

满足多个方向时自主选择。前期学习后转向就业、同时满足深造与就业均有已验证的实际行动路径，操作示例在 mvp.test.js 的 route 场景中。

## 投入档位、固定活动与连续流程

按“讨论.txt”的三项意见调整：16 项常规行动与 11 个事件选项采用 2～3 个完整投入档位，删除滑块和数字输入。每档直接指定资源成本与时间，不再通过连续数值和向上取整计算时长。自主学习为“简单温习”6 精力／1 时间、“按计划自习”12／2、“集中攻克难点”20／3；信息类背景每档少耗 3 点精力，时长不变。其他活动按情境配置档位名称与成本。规则层也拒绝非档位数字。

天佑会堂的普通观演恢复固定安排：时间 1、精力 2、票钱 40，心情回报 8、社交回报 2，照常按属性上限截断。没有票价或预算选项，观演本身不抽取回报随机数；地点相关的讲座等突发事件仍遵循原触发规则。

军训开始前选择整体安排：基本完成为 10 精力／2 时间，认真训练为 18／3，加练为 26／4。该成本覆盖训练与汇演，开始时一次扣除。训练回顾后直接进入汇演；汇演免费完成并记录军训经历，普通行动、学期结算以及其他事件均等待军训结束。资源不足以支付全程时不能开训，可选择请假。旧档若仍在本学期行动阶段且已开训但未完成，会优先续接汇演，保留其他待处理事件。

确认前只展示活动情境、档位成本、当前资源和前置条件，继续隐藏数值回报、平均收益、范围与概率。完成后显示实际变化及贴合活动的叙述，成长记录、保存和重放保留结果。

配置集中在 config.js 的 ACTION_TIERS、EVENT_TIERS，以及 ACTION_INVESTMENTS、EVENT_INVESTMENTS。每档包含 id、label、amount、time。内部回报沿用 q=x/(x+h)、a=1+2q、系数=(1-s)×a/(a+1)+s×U^(1/a)，取 round(R×q×系数) 并截断到属性上限。函数只计算选定档位的回报，已不接受任意数值。项目、社团和实习仍按原有申请、两次投入与成果确认推进。

历史存档已结算的任意投入、旧观演回报及军训记录保留原值。LEGACY_INVESTMENTS 仅供校验与展示旧记录，不作为新行动选项。新日志记录档位；旧版本日志应在对应版本重放。

本轮验收见 [档位与军训连续流程验收](qa/档位与军训连续流程验收-20261029.md)。之前各版本的验收记录保留于 qa/，须对应各自版本的规则阅读。

## 保存与继续

提供 3 个独立存档栏位。点击保存可选择栏位，覆盖已有内容前确认；入学页及读取面板可选择任一有效栏位或该栏上一备份。每栏显示昵称、学期和保存时间。旧版单存档直接作为栏位 1。

地图及事件、总结、结果弹窗可手动保存；首次保存或读取后，学期结算和最终方向确认自动保存到当前栏位。新局尚未选栏时，结算会明确提示手动选栏，不自动覆盖其他存档。读取恢复阶段、事件队列、投入进度和随机数当前位置。

保存采用临时档回读、有效主档备份、主档替换与确认。主档损坏时展示有效备份供主动恢复；存储失败保留内存进度。未知格式或规则版本不加载，程序版本标记只用于定位发布。标签页冲突阻止覆盖，需先读取最新存档。

本轮未提供存档 JSON 导入或旧规则迁移。概要设计文档已补充第 7 部分模块接口和第 8 部分存档与数据结构，完整文档见 [北交人生概要设计](docs/北交人生_概要设计_V0.1.docx)，代码接口说明见 [第 7 与 8 部分实现说明](docs/概要设计第7与8部分实现说明.md)。

## 测试与复现

    node --test
    node scripts/check-release.js

地址添加 ?debug=1 进入测试模式：新局可设置种子，地图显示阶段、规则版本、revision、随机调用数，并可下载复现日志。普通页面不显示内部字段。

日志包含初始昵称与种子、成功操作序列、失败原因、操作前后摘要和最终状态。将日志中的 nickname、seed、commands 传给 CampusGame.replay()，可复现成功操作后的完整状态。失败操作不改变规则状态，单独列入 failures。

当前共 117 项自动测试通过：规则及路线 41 项、存档专项 21 项、界面协调 22 项、音频 6 项、事件集成 8 项、事件档位 6 项、常规档位 5 项、新版流程 8 项。事件调度修复及对应浏览器检查见 [事件调度与时间线修复记录](qa/事件调度与时间线修复记录-20261021.md)。此前0.3.0版的全部五分支集成、八学期浏览器毕业、读档及视口检查见 [全分支本地集成验收记录](qa/全分支本地集成验收记录-20261021.md)，其日志须对应当时的代码重放。手机真机、独立 Chrome/Edge 和线上验收仍待执行。

M4 首次主线集成的 76 项测试、冲突处理和接口对接记录见 [M4 主线集成记录](qa/M4主线集成记录.md)。原有规则与浏览器记录见 qa/MVP验证记录.md，存档职责和接口见 [M4 模块交付说明](docs/M4模块交付说明.md)，发布操作见 [M4 部署说明](docs/M4部署说明.md)。
