# BJTU Life Simulator 北交人生

软件开发与测试综合实践网页 MVP。程序版本 0.3.0，规则版本 3，存档格式版本 1。沿用现有 HTML、CSS、JavaScript 和校园地图，无需业务服务器或账号。

## 运行

在本目录启动静态 HTTP 服务，例如：

    python -m http.server 8765

然后打开 http://127.0.0.1:8765/ 。部署时将页面、脚本和 assets 一起发布到固定站点。

双击 index.html 可试用界面；正式存档和验收使用 HTTP/HTTPS。不同协议、域名、端口、浏览器各自拥有独立存档。

## 本轮确定的玩法

- 保留成绩、社交、体能、心情、钱包五项核心属性。时间与精力是行动资源。
- 学习只有一项“本学期学习进度”，内部字段 preparation。课程、自学、补习和项目投入都使用它，不另设平时分、学识或专业能力。
- 期末成绩固定为 Math.round(40 + preparation * 0.6)。下学期学习进度清零，八学期成绩记录保留。
- 初始时间 12、精力 80、钱包 1000、社交 20、体能 50、心情 70；每学期生活支出 300，资金不足由援助补足。
- 保留旧版休息收益：精力已满但心情未满时仍可改善心情，两者都满才禁用。
- 十一个地图入口均可行动：思源楼（课程）、图书馆（自习与深造）、逸夫楼（项目）、学生活动中心（社团）、宿舍（休息交流）、南门（勤工与求职）、操场（锻炼）、银杏大道（散步）、校医院（体检与看病）、红果园宾馆（校友接待志愿）、天佑会堂（看演出）。
- 填写昵称后，随机分配简化学院类别和专业方向。信息类自学减少精力消耗、工程类项目增加学习收益、经管类社团增加社交收益。背景不锁定路线。
- 原“校外兼职”改为虚构的校内勤工助学；实习通过校内申请与经历进度模拟。

## 事件与方向

项目、社团、实习各有申请、投入、成果确认三个主要节点。接受邀请后投入两次；项目和社团须进入加入之后的学期再确认，实习可在两次投入后确认。未完成投入到期时延期并保留进度，最后学期仍未完成则记为未完成。成果确认可完成、延期或免费放弃。

项目第 2～6 学期开放申请，要求本学期学习进度 40。社团第 1～6 学期的秋季开放。实习第 5～7 学期开放，要求已结算平均成绩 60。大三起开放深造和求职准备，准备进度跨学期保留。

保留室友关心与体测体验。每学期首次自学有 35% 概率从随机日常池抽中一个事件；随机过程统一使用带种子的 mulberry32，普通活动和成绩不随机。

本版本新增三类事件：

- 固定事件：大一军训（开训、汇演两阶段）、大三转专业通知、大三下深造宣讲会、补考通知（上学期有课程未达标时）、大四毕业季。固定事件自本学期第二次行动起触发，每学期至多一次。
- 多阶段事件链：校园歌手大赛（秋季报名→复赛→决赛，同学期推进）、春运回家（秋季抢票→下学期上车→再下一学期分享特产，跨学期推进）、学科竞赛（大三招募→决赛答辩）。链节点按事件历史推进，拒绝或中断即不再触发后续节点。
- 随机日常池：图书馆讨论、校园猫、食堂新窗口、捡到校园卡、表白墙点名、占座之争、深夜卧谈、球场崴脚、换季流感、失眠、会堂讲座、毕业大戏、校友分享会、宾馆周末帮工，以及仅秋季入池的北京初雪与快递爆仓。每学期首次自主学习抽取一次，命中概率 35%，按同一次抽取值选择池中事件，随机数调用次数与旧版一致。
- 新增经历类型：军训（military）、歌手大赛（singer）、返乡（trip）、竞赛（contest），每局至多记录一次，并纳入存档校验白名单。

| 方向 | 条件 |
| --- | --- |
| 普通毕业 | 平均成绩至少 60，且至少六学期达标 |
| 继续深造 | 基础毕业条件、平均至少 80、完成项目、深造准备至少 60 |
| 进入就业 | 基础毕业条件、完成实习、求职准备至少 60 |
| 暂未达到毕业条件 | 未满足基础毕业条件，仍展示记录并结束 |

满足多个方向时自主选择。前期学习后转向就业、同时满足深造与就业均有已验证的实际行动路径，操作示例在 mvp.test.js 的 route 场景中。

## 保存与继续

提供 3 个独立存档栏位。点击保存可选择栏位，覆盖已有内容前确认；入学页及读取面板可选择任一有效栏位或该栏上一备份。每栏显示昵称、学期和保存时间。旧版单存档直接作为栏位 1。

地图及事件、总结、结果弹窗可手动保存；首次保存或读取后，学期结算和最终方向确认自动保存到当前栏位。新局尚未选栏时，结算会明确提示手动选栏，不自动覆盖其他存档。读取恢复阶段、事件队列、投入进度和随机数当前位置。

保存采用临时档回读、有效主档备份、主档替换与确认。主档损坏时展示有效备份供主动恢复；存储失败保留内存进度。未知格式或规则版本不加载，程序版本标记只用于定位发布。标签页冲突阻止覆盖，需先读取最新存档。

本轮未提供存档 JSON 导入或旧规则迁移。概要设计文档已补充第 7 部分模块接口和第 8 部分存档与数据结构，完整文档见 [北交人生概要设计](docs/北交人生_概要设计_V0.1.docx)，代码接口说明见 [第 7 与 8 部分实现说明](docs/概要设计第7与8部分实现说明.md)。

## 测试与复现

    node --test
    node scripts/check-release.js

地址添加 ?debug=1 进入测试模式：新局可设置种子，地图显示阶段、规则版本、revision、随机调用数，并可下载复现日志。普通页面不显示内部字段。

日志包含初始昵称与种子、成功操作序列、失败原因、操作前后摘要和最终状态。将日志中的 nickname、seed、commands 传给 CampusGame.replay()，可复现成功操作后的完整状态。失败操作不改变规则状态，单独列入 failures。

当前共 87 项自动测试通过：原规则及路线 41 项、存档专项 21 项、界面协调 15 项、音频 6 项、新事件集成 4 项。2026 年 10 月 21 日已核对全部五个远程分支，并在本地浏览器完成八学期毕业、各阶段读档、双标签冲突、备份恢复及桌面/390 像素视口检查，详见 [全分支本地集成验收记录](qa/全分支本地集成验收记录-20261021.md)。手机真机、独立 Chrome/Edge 和线上验收仍待执行。

M4 首次主线集成的 76 项测试、冲突处理和接口对接记录见 [M4 主线集成记录](qa/M4主线集成记录.md)。原有规则与浏览器记录见 qa/MVP验证记录.md，存档职责和接口见 [M4 模块交付说明](docs/M4模块交付说明.md)，发布操作见 [M4 部署说明](docs/M4部署说明.md)。
