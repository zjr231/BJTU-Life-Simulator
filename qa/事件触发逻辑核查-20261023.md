## 2. 阅读触发条件的统一口径

每学期12点时间，以下“已用时间”指`12 - state.time`。普通行动先扣资源、加属性，再判断事件，因此所有阈值都应检查行动后的数值。事件选项本身也会消耗时间，但处理选项不会立即开启下一个可选校园日程或随机日常。

奇数学期1/3/5/7为秋季，偶数学期2/4/6/8为春季。当前阶段标签：已用0～4为学期初、5～8为学期中、9～12为学期末。部分校园日程的窗口从已用4开始，不能仅凭“学期中”标签推断触发时点。

除特别说明外，同一节点每学期处理后不再出现。触发还受事件优先级影响：已有待处理事件或必要队列时，不新增可选校园日程与随机日常。一次普通行动至多新增一个可选校园日程；低心情、体测、补考和主动申请/成果确认仍可能排队。

## 3. 全部38个节点

### 3.1 条件通知：3个

| ID | 事件名称 | 实际触发条件 | 应重点测试 |
| --- | --- | --- | --- |
| roommateCare | 室友的关心 | 调度时心情严格小于30；跨学期仍低心情也触发 | 行动后29触发、30不触发；每学期一次；低心情与体测并发顺序 |

### 3.2 主动申请及确认：6个

| ID | 事件名称 | 实际触发条件 |

### 3.4 随机日常：16个节点

下表列出可触发的行动，并非保证触发。都需要当前没有其他待处理/排队事件，且当学期随机机会尚未使用。

| ID | 事件名称 | 可触发行动 | 额外窗口 |
| --- | --- | --- | --- |

| cat | 台阶上的猫 | 自主学习、散步 | 无 |
| canteen | 食堂新窗口 | 自主学习、散步、室友交流、锻炼 | 无 |
| card | 地上的校园卡 | 自主学习、散步、锻炼 | 无 |
| wall | 表白墙点名 | 自主学习、室友交流 | 无 |
| seat | 占座之争 | 自主学习 | 无 |
| snow | 北京初雪 | 散步 | 秋季，已用时间至少9 |
| parcel | 快递爆仓 | 室友交流 | 秋季，已用时间至少6 |
| night | 深夜卧谈 | 室友交流 | 无；目前没有昼夜系统 |
| injury | 球场上的崴脚 | 锻炼 | 无；不检查低体能或疲劳 |
| flu | 换季流感 | 室友交流 | 秋季，已用时间至少4 |
| insomnia | 失眠的夜 | 室友交流 | 无；不检查低心情或低精力 |
| lecture | 会堂的讲座 | 看演出 | 无 |
| drama | 毕业大戏 | 看演出 | 春季，已用时间至少9；不限大四 |
| alumniStory | 校友分享会 | 校友接待志愿 | 无 |
| frontDesk | 周末帮工 | 校友接待志愿 | 无 |

具体抽取规则：

1. 筛选当前行动、季节和时间窗口匹配的事件池。普通课程学习、休息等未配置场景的行动不抽取。
2. 没有其他事件占用时，从统一种子随机数序列抽一个值r，并立刻设置randomCampusRoll:学期为true。
3. r严格小于0.35才出现事件；r等于0.35不出现。
4. 命中时用同一个r在当前候选池内等概率选择一个事件，不额外调用一次随机数。
5. 无论命中与否，本学期都不再抽取；新学期才有下一次机会。

因此“每次点击35%触发”不是当前规则。前期自习或交流已经抽过，后期初雪/快递/毕业大戏就没有机会再抽。即使八学期都用上机会，随机日常的期望总数也仅为8×0.35=2.8个，每局最多8个。这解释了事件配置不少但玩家可能感到随机内容偏少的现象。

对固定种子audit-stat-0～audit-stat-9999的首次自学做10000次抽样：3445次命中，命中率34.45%。六个候选事件各出现556～614次。该结果仅是此场景与种子样本的统计检查；精确阈值另由注入随机值的边界测试验证。

## 4. 已复现的设计/实现差异

### 4.1 歌手链可以挤掉转专业与竞赛窗口

合法操作步骤：前面学期每学期学习两次并正常结算，其他事件均选later；进入第3或第5学期后：

1. 学习两次，已用4，出现歌手报名；选择signup，已用5。
2. 休息一次，已用6，出现复赛；选择advance，已用7。
3. 再休息一次，已用8，出现决赛；选择perform，已用10。
4. 继续行动到学期结束，转专业/竞赛招募的4～7窗口已经过去。

原因：歌手节点优先级25/26/27，竞赛招募55、转专业70；一次行动只选一个可选校园事件。对照路径在歌手报名选择later，再休息一次，已用5时可以出现转专业/竞赛招募。

两条路径均通过validateState，且操作日志通过replay完整复现。当前行为已确认；是否算缺陷取决于需求是否允许这些通知被静默错过。建议区分“必须展示的通知”和“可错过的活动”，对必须展示的通知增加独立待办、保护窗口或明确错过提示。

### 4.2 部分文案没有对应业务后果

- 转专业通知选择apply只扣时间/精力并改变心情和社交，不修改background或major，也没有后续审批链。
- 补考通知选择retake只扣时间、精力、钱包并改变心情，不修改历史课程成绩和达标学期数，也没有后续补考结算。
- 伤病、流感、失眠当前没有持续状态；免费“忍着/硬扛”选项不会再随机判定恶化。

前两项已通过合法操作和前后状态比对确认。它们不代表触发器判断失败，但如果需求承诺实际转专业、补救成绩或持续病情，则业务实现尚未完成。

### 4.3 阶段标签与日程窗口口径不完全一致

已用4时地图仍显示学期初；歌手报名、转专业、竞赛招募、深造宣讲的配置窗口却都从4开始。建议统一文案或阈值，测试时先按数值判断，不按“中段”描述判断。

| 测试维度 | 代表用例 | 预期 |
| --- | --- | --- |

| 事件选项 | 时间/精力/钱包恰好够，以及逐项差1 | 恰好够可选；不足不扣费、不改状态 |
