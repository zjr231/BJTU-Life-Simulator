# 第 5 批优化：未保存离开保护

基于 `main` 的 `bd0710a`，日期：2026-10-30。

## 问题与修改

页面会显示当前进度是否已保存，但刷新、关闭标签页或返回时没有离开提醒。考试草稿、刚完成的行动和事件结果在没有保存栏位或尚未再次保存时可能丢失。

现在只有存在游戏且当前 `revision` 与最近一次成功保存的版本不一致时，才拦截 `beforeunload` 并交给浏览器显示离开确认。没有开始游戏，或当前进度已经保存时不会弹出无意义的提示。提醒只保护页面离开，不自动写入存档，也不改变规则与存档格式。

## 验证结果

- `node --test`：197 项全部通过。
- `node scripts/check-release.js`：发布资源路径、大小写、脚本语法和加载顺序检查通过。
- `git diff --check`：通过。
- 新增界面回归覆盖无游戏、未保存新局、成功保存后、保存后再次行动四种状态。
- Chrome 155 浏览器复测：入学页刷新不弹确认；开始游戏后刷新出现 `beforeunload`；取消后游戏页仍在；成功保存后刷新不弹确认。

## 手动复查

1. 开始新局后刷新页面，浏览器应提示有未保存更改。
2. 保存到任一栏位后刷新页面，不应重复提示。
3. 保存后再执行一次行动，刷新页面应重新提示。
4. 在入学页或没有开始游戏时刷新，不应出现离开确认。

浏览器自定义确认文案由浏览器决定。浏览器对同一页面连续取消离开确认后的重复弹窗有自身抑制规则；业务逻辑各保存状态由自动化回归单独验证。本批未执行推送。
