# 公司库与岗位库设计（实习·求职系统 前置设计）

> 状态：设计稿 v1（2026-11-03，覃竟峰/M3 起草，团队讨论稿，未实现）
> 本文是实习与求职系统重设计的**前置数据设计**。实现分期见文末「实施衔接」。

## 1. 定位与背景

现行实习系统是单一事件链（申请→入职→投入×2→产出证明），仅第 5–7 学期开放、门槛只有平均成绩，且全游戏只有"一个实习"。现实复杂得多：大二就有实习；有的实习去了就有，有的要拿项目/竞赛/前段实习换；先选公司岗位、再倒推准备。

本设计把抽象分层实体化为**公司库 + 岗位库**：

- **岗位是核心实体**（门槛、收益、窗口、亲和都挂在岗位上），公司是岗位的风味前缀与厂级标签
- 玩家体验改为**目标驱动**：浏览岗位 → 锁定意向 → 抽屉显示"离目标岗位还差什么" → 按差距安排学期
- 打怪升级：小厂 T1 → 中厂 T2 → 大厂 T3，每段经历为下一级门槛供弹
- 简历（`game.resume(state)`，规划中）是门槛判定的唯一口径：岗位 `requires` 引用的要件与简历展示同源

## 2. 已定决议（2026-11-03 讨论）

1. **公司名一律虚构谐音**（如 音符跳动/京西/日之亮面），避免侵权；原型对照仅限本文档内部参考
2. **规模扩大**：约 22 家公司 / 44 岗，分两批实现（信息线 16 岗先行打样）
3. **跨专业相对自由**：所有岗位全专业可见可申，高级岗位用门槛挡；专业亲和是**门槛减免**而非锁死
4. **意向锁定要做**：存档加可选字段 `targetPosition`，抽屉「往哪走」显示与目标岗位的差距
5. **必须有硬核岗（且-门槛）与易上手岗并存**，支撑"小厂→中厂→大厂"升级体验

## 3. 通用规则

### 3.1 岗位档位（tier）

| tier | 定位 | 开放窗口 | 通用门槛 | 对口专业门槛（亲和减免） |
|---|---|---|---|---|
| **T1 起步** | 去了就有 | 第 3–7 学期 | 平均成绩 ≥ 60（初创类 ≥ 50） | 同通用（T1 不设减免） |
| **T2 进阶** | 中厂核心 / 大厂普通岗 | 第 5–7 学期（个别 4 起） | 简历要件：项目 / 竞赛 / 前段实习，**至少其一** | 对口专业成绩线降 10（如 60→50） |
| **T3 顶配** | 大厂核心 / 硬核岗 | 第 6–7 学期 | 项目 **且** 竞赛（AI Infra 型：项目 **且** 前段 T2 实习） | 降为 **或**（且→或） |

- 「简历要件」由 `game.resume(state)` 判定（规划中的纯函数），与简历展示同一口径，绝不另造第二套判定
- 「前段实习」= `experiences` 中已有任意一段 completed 实习；多段实习：链 completed 后**隔一学年可再申**（第 2 段自然落在大三），存档零新字段（`experiences` 天然支持多段）

### 3.2 专业亲和

- 信息类：计算机科学与技术 / 通信工程 / 软件工程 / 人工智能
- 工程类：土木工程 / 交通运输 / 机械工程 / 电气工程及其自动化
- 经管类：经济学 / 金融学 / 会计学 / 工商管理
- **交通运输为北交底色专业，享受三线跨亲和**（凡标注亲和含"交通运输"的岗位均生效）
- 亲和是减免不是锁死：非对口专业满足通用门槛照样申

### 3.3 产出框架（数值为初稿，待打样后平衡）

| tier | 段收入 | 求职准备 | 简历产出 |
|---|---|---|---|
| T1 | 300–450 | +10 | 实习经历 ×1 |
| T2 | 500–700 | +20 | 实习经历 ×1 |
| T3 | 800–1000 | +30 | 实习经历 ×1（优质段标记） |

- 收入按整段（申请 1 时间 + 投入×2 共 4 时间 + 事件若干）折算，与勤工助学（200/行动、上限 3 次/学期）平行比较后调平
- 岗位可在框架上做风味偏移（如运维体能消耗大、审计 mood 惩罚重），偏移量写在岗位条目

### 3.4 意向锁定（targetPosition）

- 玩家在岗位列表中标记一个目标岗位，可随时更换
- 存档新增**可选字段** `targetPosition`（岗位 id 或 null）——参照 `cardDebt` 先例，旧存档不迁移可读，不算格式断裂
- 抽屉「往哪走」：锁定后首卡显示"离 目标岗位 还差：各要件 ✓/✗ + 成绩差"；未锁定维持现状（四方向差距）
- 目标岗位的门槛未满足时，`advisories` 的 idle 提示语改为指出缺什么要件（复用 ADVISORIES 模板机制）

## 4. 数据模型草案（实现时落 config.js `POSITIONS`）

```js
const POSITIONS = {
  yinfu_backend: {
    company: 'yinfu',        // 公司 id → COMPANIES 表（名称/厂级/线）
    title: '后端开发实习生',
    tier: 2,                 // 1 | 2 | 3
    window: [5, 7],          // 开放学期窗
    requires: { resume: ['project', 'contest', 'internship'], // 至少其一
                grade: 60 },   // 平均成绩线
    affinity: { majors: ['计算机科学与技术', '软件工程'], gradeDiscount: 10 },
    rewards: { income: 600, jobPreparation: 20 },
    flavor: '面试官问你项目里最难的一个技术点，你答了十分钟。'
  }
  // ...
};
```

公司表（`COMPANIES`）：`{ id, name, tierClass: 'startup'|'mid'|'major'|'soe', line: 'information'|'engineering'|'management'|'cross' }`。`tierClass`（厂级）用于文案风味与第三期就业结局细分，不影响门槛（门槛只在岗位 tier 上）。

### 6.6 薪资表（wages）与完成要求（workRequirement）

| tier | 轻档日薪 | 中档日薪 | 重档日薪 | 时间门槛 | 精力门槛 |
|---|---|---|---|---|---|---|
| T1 | 50 | 100 | 150 | ≥ 4 | ≥ 24 |
| T2 | 80 | 160 | 240 | ≥ 6 | ≥ 40 |
| T3 | 120 | 240 | 360 | ≥ 9 | ≥ 70 |

- 累计口径：时间 = 档位固定耗时，精力 = 档位投入量；达标 = 累计 ≥ 门槛（时间与精力都要满足）
- T3 重度档时薪 120/时间 > 勤工助学的 100/时间——**达标后继续干赚钱成立**；不设每学期次数上限，由时间（12）与精力（80）天然约束（重度档一学期约 3 次）
- T3 门槛必跨 2 学期：**顶配岗最迟第 6 学期申请**（第 7 学期才申请会在第 8 学期被判未完成）；体验过紧可调 {6, 50}
- 数值为打样初稿，随 50 人试用窗口平衡

### 6.7 三期完成机制说明

1. **门槛挂岗位**（`workRequirement: {time, energy}`），链上累计实际投入（`workTime`/`workEnergy`），达标 = 两项累计都 ≥ 门槛
2. **达标 ≠ 自动结束**：达标瞬间弹「实习的十字路口」事件——马上办证明（结算段收入 + 求职准备 + 经历入档）/ 继续实习（继续投入赚日薪）
3. **手动结束**：达标后南门实习投入卡出现「办理实习证明」按钮，随时结算
4. **不设每学期次数上限**：时间与精力本身就是约束，玩家自行权衡继续赚钱与学业事件
5. **旧档兼容**：旧链 `progress ≥ 2` 视为已达标（grandfather）；`internshipReview` 退役为 legacy-only（保留定义供旧档读取，不再入队）
6. **多段实习**：每段经历独立记录岗位（`experiences[].positionId`），简历与门槛判定按段生效；完成一段后**下一学期即可申下一段**（同一时间只有一段，事件按学期去重）
7. **毕业保底**：第 8 学期结算时，已达标的实习自动收尾（段收入 + 求职准备 + 经历照常结算），不会因为忘记点「办证明」而被判未完成；未达标的仍按未完成处理

## 7. 打样批次与数值平衡

- **第一批（打样）：信息线 16 岗**。目标：验证 POSITIONS 数据形态、requires/affinity 字段是否够用、产出框架是否与勤工助学/求职准备行动平衡、意向锁定的抽屉联动体验。打样期允许改字段结构，改完再铺量
- **第二批：工程 + 经管 28 岗**，按第一批定稿的字段批量填充
- 数值平衡在 50 人试用窗口统一校准（与既定"试用后数值平衡"迭代合并）
