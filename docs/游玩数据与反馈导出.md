# 游玩数据与反馈导出

云服务器部署本版后，游戏通过同站点的 `POST /api/playthroughs` 接收游客、登录玩家的存档、主动退出快照和反馈。它与 NPC 接口共用 Node.js 24 服务，独立于模型密钥。部署包的 `site/` 包含本版网页、脚本及 `playthrough.js`，`service/` 包含服务脚本和数据库脚本；步级报表脚本 `scripts/playthrough-report.js` 从仓库运行。使用本版 `install-npc-service.sh` 更新站点和接口。仅提供静态网页的站点需要另行接入后端。

反馈邀请在第二学期（大一下）总结后自动出现；此前从设置主动退出也会出现。设置里的“反馈与建议”可随时补交。自动邀请每局只出现一次，玩家可勾选“以后不再自动提醒”；手动反馈不受此限制。直接关闭浏览器标签页无法弹自定义反馈表单，只能由下一次手动保存、学期结算或主动退出留下记录。

数据库升级不会删除旧的 `game_feedback` 表；新反馈写入 `game_feedback_entries`，旧表保留给回滚后的旧服务使用。回滚旧服务后看不到升级后新增的后续反馈，但不会因表结构变化而启动失败；再次升级时旧表记录会补入新表。

## 在本机试玩

在仓库根目录用 Node.js 24 执行 `node scripts/preview-game.js`，打开 `http://127.0.0.1:8765/`。本机存档和反馈写入当前用户目录下的 `.bjtu-life-preview/playthroughs.sqlite`。在 PowerShell 中可将两份试玩数据导出到临时目录，命令会打印本次导出的完整路径。

```powershell
node scripts/playthrough-store.js export "$env:USERPROFILE/.bjtu-life-preview/playthroughs.sqlite" $env:TEMP
```

## 在服务器导出

默认数据库为 `/var/lib/bjtu-npc/playthroughs.sqlite`。在服务器的管理员终端执行以下命令。两份文件取自同一时刻的数据库，游戏可继续运行。

```bash
export_dir=$(sudo -u bjtu-npc /opt/bjtu-npc/current/node \
  /opt/bjtu-npc/current/scripts/playthrough-store.js export \
  /var/lib/bjtu-npc/playthroughs.sqlite /tmp)
```

将本次导出的目录交给维护账号，再打印下载路径。

```bash
sudo chown bjtu-maint "$export_dir/game_saves.jsonl" "$export_dir/game_feedback.jsonl" "$export_dir"
echo "$export_dir"
```

在自己电脑的 PowerShell 中执行下面的命令，把服务器地址和目录名换成实际值。文件会下载到当前目录。

```powershell
scp -r bjtu-maint@服务器公网地址:/tmp/bjtu-analysis-实际后缀 .
```

## 如何关联与统计

| 文件 | 每一行的含义 | 常用字段 |
| --- | --- | --- |
| `game_saves.jsonl` | 一次手动保存、自动保存、主动退出或反馈时的完整游戏状态 | `run_id` 对局编号，`snapshot_id` 快照编号，`kind` 类型，`slot` 栏位，`term` 学期，`phase` 阶段，`ending` 结局，`state` 完整存档 |
| `game_feedback.jsonl` | 玩家提交的一条反馈 | `id` 反馈编号，`run_id`，`snapshot_id`，`source` 来源，`suggestion`，`received_at` |

- 按 `run_id` 分组可还原一局内的多次存档。统计有记录的局数时对该字段去重。每次新开局使用新编号，继续游戏、恢复备份和另存到其他栏位沿用原编号。
- 用反馈的 `run_id` 和 `snapshot_id` 一起匹配存档，即可定位玩家提交建议时的状态。玩家跳过反馈时，存档和退出快照仍然保留。
- `kind` 为 `manual`、`auto`、`ending`、`exit` 或 `feedback`。`exit` 表示玩家在游戏内主动退出；`feedback` 表示从第二学期邀请或设置入口提交反馈时关联的快照。`exit` 和 `feedback` 的 `slot` 可以为空。
- `source` 为 `term2`、`exit`、`ending` 或 `settings`。`term2`、`exit`、`ending` 每局最多一条；`settings` 是后续补交，可多条。旧版本反馈迁移后统一记为 `ending`。
- 同一结局、同一退出状态或同一反馈快照只保留一份；网络重试不会重复增加快照。自动来源的反馈也只保留一条。
- `saved_at` 为玩家设备记录的时间，`received_at` 为服务器接收时间，单位均为 Unix 毫秒。断网补传时两个时间可能相差较久。
- 完整存档包含玩家昵称、行为与人物对话，建议可能含玩家自行填写的信息。导出文件只交给负责分析的团队成员；建议先删除昵称和对话原文再共享步级报表。

## 生成步级数据

`scripts/playthrough-report.js` 会读取数据库或已导出的目录，按每个对局的最新快照重放完整命令序列，输出每一步操作的前后状态、即时变化、学期成绩和反馈关联。它不修改线上数据库。

```powershell
node scripts/playthrough-report.js "$env:USERPROFILE/.bjtu-life-preview/playthroughs.sqlite" .\analysis-output
```

输出文件：

| 文件 | 内容 |
| --- | --- |
| `runs.csv` | 每局一行：最终学期、结局、平均成绩、步数、反馈数、重放状态 |
| `steps.csv` | 每一步操作的行动、投入、前后资源、即时 delta、事件/对话信息 |
| `terms.csv` | 已结算学期的课程、考试和总评 |
| `term_actions.csv` | 每局每学期的行动次数和累计资源变化 |
| `feedback.csv` | 反馈来源、文本，以及关联快照的学期和结局 |
| `manifest.json` | 对局、步骤、反馈数量和重放失败数 |

重放失败的对局会保留 `replay_ok=0` 和错误原因，不会静默丢弃。新行动或旧存档兼容问题优先检查这里。

## 回归分析

分析脚本使用离线 Python，不进入网页发布包。首次使用安装依赖：

```powershell
python -m venv .venv
.\.venv\Scripts\python -m pip install -r analysis\requirements.txt
.\.venv\Scripts\python analysis\balance_model.py --input .\analysis-output --output .\balance-output
```

输出：

- `action_descriptives.csv`：行动使用次数、平均收益、单位时间和单位精力收益。
- `action_effects.csv`：步级面板回归的行动系数、聚类标准误、置信区间和样本量。
- `outcome_effects.csv`：整局行动次数与最终平均成绩的探索性关联。
- `term_effects.csv`：本学期行动次数与期末总评的学期面板模型。
- `exit_hazard.csv`：主动退出风险的探索性 Logit 模型。
- `balance_report.md`：面向策划的阅读版，包含过强、过弱和资源瓶颈的复核线索。

模型使用行动虚拟变量、学期固定效应、操作前资源控制和按对局聚类标准误。它描述条件关联，不是因果关系；玩家会根据自己的资源和目标选择行动。要验证某项数值改动的实际效果，应使用相同种子和操作序列做反事实重放，或进行小规模对照实验。样本量不足的行动不会给出可靠结论。

## 在 Excel 中查看下载的数据

打开 Excel，依次选择「数据 → 获取数据 → 从其他源 → 空白查询」，在 Power Query 编辑器打开「高级编辑器」。粘贴以下查询，把第一行路径变量的值换成下载文件的实际位置，然后选择「关闭并上载」。每一行反馈会显示在工作表中，建议里的换行会保留。

~~~powerquery
let
    路径 = "D:\游戏分析\game_feedback.jsonl",
    行 = Lines.FromBinary(File.Contents(路径), QuoteStyle.None, false, 65001),
    记录 = List.Transform(List.Select(行, each Text.Trim(_) <> ""), each Json.Document(_)),
    列 = if Text.EndsWith(路径, "game_feedback.jsonl")
         then {"id", "run_id", "snapshot_id", "source", "suggestion", "received_at"}
         else {"run_id", "snapshot_id", "kind", "slot", "term", "phase", "ending", "saved_at", "received_at"},
    结果 = Table.FromRecords(记录, 列, MissingField.UseNull)
in
    结果
~~~

复制这条查询，把文件名换成 `game_saves.jsonl` 即可得到存档表。在「合并查询」中以反馈表为第一张表，按住 Ctrl，在两张表中依次选择 `run_id`、`snapshot_id`，再展开存档的 `term`、`ending` 列，就能看到每条建议对应的学期和结局。
