# 游玩数据与反馈导出

云服务器部署本版后，游戏通过同站点的 `POST /api/playthroughs` 接收游客、登录玩家的存档和结局反馈。它与 NPC 接口共用 Node.js 24 服务，独立于模型密钥。部署包的 `site/` 包含本版网页、脚本及新增的 `playthrough.js`，`service/` 包含本版服务脚本及新增的 `scripts/playthrough-store.js`。使用本版 `install-npc-service.sh` 更新站点和接口。仅提供静态网页的站点需要另行接入后端。

## 在本机试玩

在仓库根目录用 Node.js 24 执行 `node scripts/preview-game.js`，打开 `http://127.0.0.1:8765/`。本机存档和反馈写入当前用户目录下的 `.bjtu-life-preview/playthroughs.sqlite`。在 PowerShell 中可将两份试玩数据导出到临时目录，命令会打印本次导出的完整路径。

```powershell
node scripts/playthrough-store.js export "$env:USERPROFILE/.bjtu-life-preview/playthroughs.sqlite" $env:TEMP
```

## 在服务器导出

默认数据库为 `/var/lib/bjtu-npc/playthroughs.sqlite`。在服务器的管理员终端执行以下命令。两份文件取自同一时刻的数据库，游戏可继续运行。

```bash
export_dir=$(sudo -u bjtu-npc /opt/bjtu-npc/current/node \
  /opt/bjtu-npc/current/scripts/playthrough-store.js export \
  /var/lib/bjtu-npc/playthroughs.sqlite /tmp)
```

将本次导出的目录交给维护账号，再打印下载路径。

```bash
sudo chown bjtu-maint "$export_dir/game_saves.jsonl" "$export_dir/game_feedback.jsonl" "$export_dir"
echo "$export_dir"
```

在自己电脑的 PowerShell 中执行下面的命令，把服务器地址和目录名换成实际值。文件会下载到当前目录。

```powershell
scp -r bjtu-maint@服务器公网地址:/tmp/bjtu-analysis-实际后缀 .
```

## 如何关联与统计

| 文件 | 每一行的含义 | 常用字段 |
| --- | --- | --- |
| `game_saves.jsonl` | 一次手动保存、自动保存或到达结局时的完整游戏状态 | `run_id` 对局编号，`snapshot_id` 快照编号，`kind` 类型，`slot` 栏位，`term` 学期，`phase` 阶段，`ending` 结局，`state` 完整存档 |
| `game_feedback.jsonl` | 一局结束后玩家实际提交的一条建议 | `run_id`、`snapshot_id`、`suggestion`、`received_at` |

- 按 `run_id` 分组可还原一局内的多次存档。统计有记录的局数时对该字段去重。每次新开局使用新编号，继续游戏、恢复备份和另存到其他栏位沿用原编号。
- 用反馈的 `run_id` 和 `snapshot_id` 一起匹配存档，即可定位玩家提交建议时的具体结局。玩家跳过反馈时，结局仍保存在存档表中。
- `kind` 为 `manual`、`auto` 或 `ending`。从未手动选择栏位也会记录结局，此时 `slot` 为空。重复打开同一结局或网络重试只计算一次该结局。
- `saved_at` 为玩家设备记录的时间，`received_at` 为服务器接收时间，单位均为 Unix 毫秒。断网补传时两个时间可能相差较久。
- 完整存档包含玩家昵称、行为与人物对话，建议可能含玩家自行填写的信息。导出文件只交给负责分析的团队成员。

## 在 Excel 中查看下载的数据

打开 Excel，依次选择「数据 → 获取数据 → 从其他源 → 空白查询」，在 Power Query 编辑器打开「高级编辑器」。粘贴以下查询，把第一行路径变量的值换成下载文件的实际位置，然后选择「关闭并上载」。每一行反馈会显示在工作表中，建议里的换行会保留。

~~~powerquery
let
    路径 = "D:\游戏分析\game_feedback.jsonl",
    行 = Lines.FromBinary(File.Contents(路径), QuoteStyle.None, false, 65001),
    记录 = List.Transform(List.Select(行, each Text.Trim(_) <> ""), each Json.Document(_)),
    列 = if Text.EndsWith(路径, "game_feedback.jsonl")
         then {"run_id", "snapshot_id", "suggestion", "received_at"}
         else {"run_id", "snapshot_id", "kind", "slot", "term", "phase", "ending", "saved_at", "received_at"},
    结果 = Table.FromRecords(记录, 列, MissingField.UseNull)
in
    结果
~~~

复制这条查询，把文件名换成 `game_saves.jsonl` 即可得到存档表。在「合并查询」中以反馈表为第一张表，按住 Ctrl，在两张表中依次选择 `run_id`、`snapshot_id`，再展开存档的 `term`、`ending` 列，就能看到每条建议对应的学期和结局。
