## 本地要移植的功能

1. 常规行动和部分事件采用固定投入档位，移除滑块与任意数值输入。每档直接配置时间和资源成本。
2. 保留饱和收益与投入相关随机分布，确认前隐藏回报；完成后显示具体活动叙述和实际变化。
3. 天佑会堂普通观演恢复固定成本与固定回报。
4. 军训选择全程安排后一次付费，训练直接进入免费汇演，期间不插入其他行动／事件；资源不足不能开训。
5. 投入结果进入成长记录与存档，新规则拒绝非档位数值，已结算旧记录保留。

主要实现：`config.js`、`game.js`、`app.js`、`styles.css`、`state-validation.js`。新增专项测试：`action-investment.test.js`、`event-investment.test.js`、`tiered-flow.test.js`；原有路线、事件和界面测试也作了相应调整。

## 明天建议的整合顺序

1. 从当天最新 main 再建立实际整合分支，先保留选课／考试、短信、NPC、DeepSeek 等主线系统。
2. 对照旧基线到本地快照的差异，提取投入档位配置、成本与随机回报、军训连续流程，再接入主线现有行动和学期接口。
3. 特别核对 `preparation` 与考试／课程成绩的关系、`examPending` 阶段、背景专业名称及旧档兼容；不要把本地“结束学期直接按学习进度算分”的流程覆盖主线考试。
4. 合并 app 的档位控件、结果叙述和成长记录时，保留登录、NPC、数学渲染与音频入口。
5. 同步状态校验与重放参数，测试军训的恢复优先级及其他事件延后处理。
6. 同时保留两侧测试，检查课程考试、短信、NPC、中转，以及本地档位、固定观演、军训与存档回归；重新检查静态脚本加载顺序。
