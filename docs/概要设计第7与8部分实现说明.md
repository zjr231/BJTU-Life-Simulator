# 北交人生模块接口与存档结构实现说明

依据 2026 年 10 月 12 日确认的需求与最终代码整理。程序 0.3.0，规则 3，存档格式 1。概要设计第 7、8 部分已补充，完整文档见 [北交人生概要设计](北交人生_概要设计_V0.1.docx)。

本轮将平时分、学识、课程准备、专业能力相关学习数值合并为一项本学期学习进度 preparation。成绩按固定公式生成，八条课程记录用于毕业平均成绩；不再设置额外专业能力门槛。体能、心情及操场、银杏大道保留。

## 第七部分 模块接口

### 依赖与调用约定

app.js 维护唯一当前状态，调用 game.js 处理操作，调用 save.js 协调保存和读取。game.js 依赖 config.js、rng.js，状态校验委托 state-validation.js。规则函数不访问 DOM、本地存储或系统时间。

浏览器加载顺序为 config.js、rng.js、state-validation.js、game.js、save.js、app.js；规则及存档模块同时支持 CommonJS，便于 Node.js 测试。

| 接口 | 作用 |
| --- | --- |
| validateNickname(value) | 校验昵称，返回 ok、value 或 reason；去除首尾空白，最多 12 字符 |
| createGame({nickname, seed}) | 返回初始 GameState；非法输入抛出错误，由界面捕获 |
| getAction(state, actionId) | 返回含背景加成的行动配置 |
| availability(state, actionId) | 只读校验阶段、资源、申请条件、次数及收益 |
| previewChanges(state, effect) | 只读计算实际增量与上下限截断 |
| executeAction(state, actionId, options) | 校验后一次性提交资源、次数、投入与触发队列 |
| eventAvailability(state, choiceId, instanceId?) | 只读检查事件实例、选项和资源 |
| submitEventChoice(state, choiceId, options) | 处理一个事件，更新标记与经历，再接续队列 |
| previewSettlement(state) | 只读返回成绩、支出、援助、余额及延期说明 |
| endTerm(state, options) | 单次提交课程记录和总结，进入 summary |
| continueGame(state, options) | 第 1～7 学期推进；第八学期评估方向进入 endingChoice |
| evaluateEndings(state) | 只读返回精确平均值、达标学期与方向条件 |
| chooseEnding(state, directionId, options) | 记录方向及条件依据，进入 finished |
| validateState(state) | 检查完整快照和引用约束，返回 ok 或 reason |
| replay({nickname, seed, commands}) | 按成功操作序列复现状态，非法步骤返回原因 |

成功变更接口返回 {ok: true, state, changes?, summary?, entry}；失败返回 {ok: false, reason, state}。app.js 仅在成功后替换 state。失败保持原 state 引用，不扣费、不追加规则历史、不推进随机数。changes 用于行动及事件数值变化，entry 包含标题、命令、序号和前后摘要。

options 公共字段：

| 字段 | 用途 |
| --- | --- |
| commandId | 一次确认的唯一字符串，最长 128 字符；重复 ID 拒绝提交 |
| expectedRevision | 必须等于当前 revision，拒绝旧面板请求 |
| eventInstanceId | 事件提交时对应当前待选实例 |

测试调用可省略 commandId 和 expectedRevision，规则生成默认编号；正式界面显式传入。成功业务操作 revision 加一，processedCommands、history 各新增一条；查看、预览和保存不增加 revision。

### 存档接口

CampusSave.createSaveService(storage, {now?}) 接收 getItem、setItem、removeItem 存储适配器，可注入保存时间以便测试。

| 接口 | 作用 |
| --- | --- |
| inspect() | 返回主档、备份校验结果及临时档存在状态 |
| save(state) | 校验快照、检查冲突、写临时档、备份、替换并确认主档 |
| load('primary' 或 'backup') | 成功返回独立候选 state、savedAt、saveSequence；失败不替换内存 |
| CampusSave.parse(raw) | 校验大小、结构深度、版本及完整状态 |

保存成功返回 ok、savedAt、saveSequence，临时键清理失败附 warning；失败返回 reason，标签页冲突附 conflict。备份失败即停止替换主档；读取有效备份由玩家主动选择，不静默覆盖损坏主档。

2026 年 10 月 16 日 M4 修正：读档的冲突基线绑定到本次实际读取的主档原文；读档中途发生的其他标签页更新会在保存时被拒绝。读档不会降低本服务已观察到的保存序号。临时档回读后、备份前增加一次冲突比较，主档确认不一致也返回 conflict，不回滚其他标签页的数据。接口字段、规则与存档格式保持兼容，专项说明见 [M4 模块交付说明](M4模块交付说明.md)。

## 第八部分 数据结构与存档

### GameState

| 字段 | 类型与含义 |
| --- | --- |
| version / rulesVersion | 当前为 3；version 保留原项目规则版本字段 |
| saveFormatVersion | 当前 1，标识状态与外层存档结构 |
| appVersion | 发布标记 0.3.0，仅用于定位程序版本 |
| nickname | 合法游戏昵称 |
| background | id、college、major，由种子确定的简化背景 |
| rng | algorithm、seed、value、calls |
| term / phase | 第 1～8 学期；playing、eventPending、summary、endingChoice、finished |
| revision / processedCommands | 成功操作序号、已提交命令数组 |
| time / energy / money | 当前时间、精力、资金，均不能为负 |
| social / fitness / mood | 0～100 的长期社交、体能、心情 |
| preparation | 0～100 本学期学习进度，下学期清零 |
| furtherStudy / jobPreparation | 0～100 深造／求职辅助准备，跨学期保留 |
| counts | 按 actionId 记录本学期行动次数 |
| courses | 最多八条、按学期排序的已结算记录 |
| summary | 当前已提交总结；未结算阶段为 null |
| chains | project、club、internship 三条事件链进度 |
| pendingEvent / eventQueue | 当前待选实例和已触发队列 |
| eventFlags / eventHistory | 已处理实例、随机机会抽取标记及选项历史 |
| experiences | 项目、组织、实习和体测完成经历 |
| history | 成功操作、命令编号、revision、前后摘要及实际变化 |
| endingOptions | 第八学期后只评估一次的方向条件快照 |
| result | 最终方向、满足／缺失条件、八学期课程与经历 |

入学待填昵称为表现层 initializing 界面，此时 state 为 null，不保存未开始的游戏；合法初始化后进入 playing。

### 事件、课程与结果

每条 chains 记录为 {status, progress, startedTerm, deadline, nextEligibleTerm, reviewAfter}。status 为 idle、active、deferred、completed、missed；progress 为 0～2 次投入。延期保留投入，完成生成一次经历，放弃或最终未完成不生成完成经历。

事件配置有稳定 ID、chain、node、priority、文字及选项，触发条件由业务层统一处理。实例为 {id, term, instanceId}，例如 project:projectReview:3 或 daily:roommateCare:2。实例、队列与标记一起存档，读档不重新抽取或发奖。

课程记录含 term、name、preparation、grade、passed、livingCost、aid、moneyAfter、unusedTime、counts、attributes、notices。grade = round(40 + preparation × 0.6)。总结必须等于最后一条课程记录，钱包与学习进度对应已提交总结。

方向快照含 average、passed、graduated、options。各方向含 id、title、available、requirements，每项条件保存 label、met、value。平均成绩使用八条记录的精确平均值，显示小数取舍不改变判定。

rng 使用 mulberry32-v1，保存 seed、当前 value 与 calls；新局学院及专业各抽一次，后续事件续用同一序列，预览不抽取。同规则、种子和操作序列可复现相同状态。

### 存档外层和恢复

JSON 外层包含 saveFormatVersion、rulesVersion、appVersion、saveSequence、savedAt、state。state 是完整 GameState，savedAt 为 ISO 时间，saveSequence 随成功保存递增。

主档键为 bjtu-life:mvp:main，备份为 bjtu-life:mvp:backup，临时为 bjtu-life:mvp:temporary。保存前比较已观察主档与当前主档，替换前再次比较，并监听其他标签页 storage 变化提示冲突；不将多个 localStorage 键当成原子事务。

存档上限 1 MiB、嵌套深度最多 14 层；检查资源范围、稳定 ID、阶段、课程条数、事件实例、完成经历、总结和结果快照。未知格式或规则版本明确拒绝；相同格式与规则允许程序版本标记变化。本轮未实现旧规则迁移与存档导入。

## 原概要设计需要同步的口径

- 第 5.1 节平时分、学识统一为本学期学习进度；自学和项目学习收益使用同一字段。
- 第 6.4 节取消额外“专业成绩”门槛：深造保留平均 80、项目、深造准备 60；就业保留基础毕业、实习、求职准备 60。
- 保留体能、心情及已有地点，因此是十一入口、八处可行动地点。
- 休息保留原型判定：精力已满但心情未满仍可改善心情，两者都满才禁用；第 5.1 节“精力满值禁用”需同步这一口径。
- 学院专业为三个简化学院类别、每类两个专业方向，并非完整真实学院专业表。
- 自动保存节点为学期结算与最终方向确认，其余阶段可手动保存。
- 已检查桌面、390 像素布局、待选及总结刷新恢复；真实体验时长、线上回归与多浏览器兼容需后续验收。
