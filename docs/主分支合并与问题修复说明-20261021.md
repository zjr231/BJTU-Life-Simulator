## 二、M4合并冲突的处理

M4与原主线共同修改了`app.js`，产生7处文本冲突。合并策略为接入三栏存档，同时保留主线剧情、音频与交互：

| 冲突位置 | 最终处理 |
| --- | --- |
| 状态栏和保存入口 | 显示当前栏位；保存、读取、覆盖确认面板不重复展示保存入口 |
| 保存成功反馈 | 提示保存到哪个栏位，并保留主线保存音效 |
| 入学页 | 保留主线昵称与入学剧情，接入三栏继续游戏及备份读取入口 |
| 新手说明 | 保留原玩法说明，补充三栏选存与自动保存规则 |
| 学期结算确认 | 根据是否已经选定栏位说明自动保存或手动选栏 |
| 读取面板 | 使用三栏列表，支持读取各栏主档或有效备份 |
| 读档成功恢复 | 提示栏位及读取来源，保留音效和背景音乐调用 |

集成还修正了测试与发布适配：模拟界面补齐`HTMLDialogElement`；测试按录取通知、教程和待选事件实际推进；五阶段存档夹具逐次检查操作结果；发布检查将`audio.js`纳入加载顺序；CI使用`node --test`发现全部测试。详情见[首次M4集成记录](../qa/M4主线集成记录.md)。

## 三、集成后发现的问题与修复

以下包含合并适配问题和整体验证中发现的已有缺陷；不将所有问题都归因于文本冲突。

| 问题 | 原表现与原因 | 修改情况 | 关键文件与验证 |
| --- | --- | --- | --- |
| 成长记录名称缺失 | 新增军训、歌手、返乡、竞赛经历后，界面的名称映射未同步，显示`undefined` | 补齐四类经历中文名称，读档后显示一致 | `app.js`、`app-save.test.js`；成长记录截图和毕业记录 |
| 重新开启声音后无背景音乐 | 静音操作取消了当前游戏的音乐播放请求，开启后无法恢复 | 静音暂停播放并保留请求，结束旧局仍取消请求 | `audio.js`、`audio.test.js`；开关、后台恢复和偏好回归 |
| 窄屏存档按钮偏小 | 新三栏按钮在390像素视口实测仅41像素高 | 最小高度改为44像素 | `styles.css`；页面尺寸实测与无横向溢出检查 |
| 开局四个事件连弹 | 军训、歌手报名、订票共用过宽的行动条件，同时入队；处理选项时再次调度，继续加入军训汇演 | 通过`CAMPUS_SCHEDULE`按学期、季节和进度选择；一次普通行动最多新增一个校园事件；处理选项不再新增可选校园事件；后续节点至少等待一次普通行动 | `config.js`、`game.js`、`events-integration.test.js`；开局操作和队列断言 |
| 订票与返乡链时间错位 | 开学就提示寒假订票；春季还在回家，再下一秋季才分享；未上车也可能继续 | 秋季末安排寒假往返车次，次年春季初返校；确认上车并继续行动后才分享；拒绝前置选项不会推进 | `config.js`、`game.js`、`app.js`；跨学期、拒绝分支和存读档验证 |
| 随机事件场景不符 | 16种日常原来均在首次自学时抽取，球场、会堂、宾馆事件也可能出现在图书馆 | 新增`RANDOM_CONTEXTS`匹配行动场景；初雪限定秋末散步、快递限定秋季后段宿舍交流、毕业大戏限定春末演出；每学期首次符合场景且无其他事件的行动抽取一次，概率35% | `config.js`、`game.js`；256个种子×两季×初末进度×六类行动，覆盖全部16种事件 |
| 玩家难以判断事件时段 | 地图只有学期名称，没有本学期进度提示 | 增加学期初／中／末；每学期12点时间，已用0～4、5～8、9～12分别对应三段 | `game.js`、`app.js`；桌面和窄屏页面检查 |

必要提示仍保留队列，例如低心情关心、体测、补考和玩家主动申请的项目/社团/实习事件。“最多一个”限制针对普通校园日程和随机日常，避免打断过密，同时保留必要的条件反馈。

## 四、兼容性与存档处理

- 程序版本从0.3.0升为0.3.1，规则3与存档格式1不变，继续使用原有三栏及旧单档兼容机制。
- 旧档已展示的事件保留，玩家可正常处理。在下一次调度时清理尚未展示的错误校园积压，再按当前窗口判断；不删除已完成历史、不重发奖励、不重置随机位置。
- 订票链只有明确选择购票、下一春季确认上车后才可进入分享节点。已经发生的历史不追溯改写。
- 同一地址的浏览器存档可继续使用。更换协议、域名、端口或浏览器会使用独立存储，文件推送不会替玩家迁移`localStorage`。
- 调度行为已经改变，0.3.0的历史复现日志须搭配当时代码重放；新版本日志对应0.3.1。学期进度是资源消耗比例，不代表具体日期或周数。
