# M4 三栏位存档说明

2026 年 10 月 16 日。基于 c005479 的 M4 增量修改，提供 3 个可自主保存、读取的栏位。各栏有独立主档、上一备份、临时数据、保存序号和冲突基线；游戏规则及存档 JSON 格式保持为规则 3、格式 1。

## 玩家操作

点击地图“保存”或弹窗“保存当前进度”，打开 3 个栏位。每栏显示昵称、学期、保存时间和上一备份；当前使用的栏位会显示标记。选择空栏立即保存，选择已有内容的栏位先确认覆盖。取消或返回重选不会改写存储，也不会切换当前自动保存栏位。

读取可在入学页直接选择，也可通过游戏内读取面板选择。每个有效主档均可独立读取；有有效备份时还可选择“恢复上一备份”。损坏或不兼容的主档不能读取，其他栏位仍可使用。读取会替换当前内存进度，面板先显示说明。

首次成功保存或读取的栏位成为当前栏位。之后学期结算和毕业方向确认只自动保存到当前栏位。手动另存成功后切换自动保存目标；另存失败时继续保留原目标。新局和重新开始都会清除当前栏位，需要重新选择，不能沿用上一局的保存目标。

新局没有选栏就结束学期时，结算照常完成，页面明确提示“尚未选择存档栏位”，由玩家点击保存选栏。此时进度只在本页内存中，不自动覆盖任何栏位。选栏、保存和取消都不推进学期、事件或随机数。

## 存储与兼容

| 栏位 | 主档键 | 备份键 | 临时键 |
| --- | --- | --- | --- |
| 1 | bjtu-life:mvp:main | bjtu-life:mvp:backup | bjtu-life:mvp:temporary |
| 2 | bjtu-life:mvp:slot:2:main | bjtu-life:mvp:slot:2:backup | bjtu-life:mvp:slot:2:temporary |
| 3 | bjtu-life:mvp:slot:3:main | bjtu-life:mvp:slot:3:backup | bjtu-life:mvp:slot:3:temporary |

栏位 1 直接复用旧键，旧版有效主档和备份无需复制、迁移或删除即可显示。外层 JSON 字段仍为 saveFormatVersion、rulesVersion、appVersion、saveSequence、savedAt、state；栏号由存储键确定，不进入 GameState。单份存档大小、深度、完整状态校验和未知规则拒绝策略不变。

每栏使用原有临时回读、有效主档备份、冲突检查、主档替换与确认流程。对不同栏位的更新不会造成彼此的保存冲突；同栏位被另一个标签页更新时，旧状态保存仍会被拒绝。storage 提示只关注当前栏位及站点存储整体被清空的情况。

localStorage 的多键操作仍不是原子事务。每个栏位是一个当前快照加上一备份，备份会随该栏后续成功保存滚动，不是无限历史记录。临时数据不自动升级，浏览器存储空间不足时保留当前内存并报告失败。

## 接口

浏览器 app.js 改用 CampusSave.createSlotService(storage, {now?})，创建后暴露：

| 接口 | 返回与约定 |
| --- | --- |
| inspect() | {ok, slots, reason}；slots 固定 3 项，各含 id、ok、primary、backup、temporary 或 reason |
| save(state, slotId) | slotId 必须显式传整数 1～3；沿用原保存返回并附 slotId |
| load(slotId, source = 'primary') | source 只接受 primary、backup；成功返回独立 state 并附 slotId |
| CampusSave.getSlotKeys(slotId) | 合法栏号返回该栏 3 个键；非法返回 null |
| CampusSave.SLOT_COUNT | 固定为 3 |

旧 CampusSave.createSaveService(storage, {now?}) 和 CampusSave.KEYS 保留给既有单档调用方与回归，仍对应栏位 1。业务规则接口及完整状态不变。今后 M2 调整保存界面时继续使用新栏位服务；M1、M3 改状态或事件结构时仍需同步兼容和校验。
