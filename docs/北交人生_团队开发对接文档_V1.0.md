```powershell
# 测试模式打开 http://127.0.0.1:8765/?debug=1
```

```powershell
node --test game.test.js mvp.test.js
```

## 3 架构与状态变更边界

### 文件依赖

浏览器脚本必须按以下顺序加载，命名空间分别为 CampusConfig、CampusRandom、CampusStateValidation、CampusGame、CampusSave；app.js 负责应用协调。

```text
config.js → rng.js → state-validation.js
          → game.js → save.js → app.js

app.js → CampusGame 处理业务操作
app.js → CampusSave 处理保存读取
game.js → config.js 与 rng.js
game.js → state-validation.js 校验完整状态
```

上述第一行表示页面加载顺序，不表示每个脚本都依赖前一个。页面和样式由 `index.html`、`styles.css` 提供，当前地图使用 `assets/campus-map-reference.png`。

`app.js` 持有唯一当前 `state`；规则函数接收旧状态并返回结果，界面仅在 `ok === true` 时替换状态并渲染。game.js 不访问 DOM、localStorage 或系统时间。保存时间由 save.js 处理，测试可注入时钟。

### 必须保持的规则

1. 界面、事件文案和存档模块不得自行扣费、发奖、推进学期或修改经历。
2. 成功业务操作使 revision 增加 1，并向 processedCommands、history 各增加一条记录。
3. 失败操作保持原 state 引用，不扣费、不增加成功历史、不推进随机数；界面可单独记录 failures。
4. 查看、预览与保存不增加 revision，也不抽取随机数。
5. 成本和前置条件在提交时再次校验；按钮禁用和 300 ms 界面锁用于交互防重，规则层仍须校验命令与版本。
6. 资源上限处反馈实际增量。例如精力 90 时休息只增加 10 精力，同时仍可增加未满的心情。

### 游戏阶段

| phase | 允许的主要业务操作 | 页面及恢复要求 |
| --- | --- | --- |
| playing | executeAction、endTerm | 地图可行动，可打开结算预览 |
| eventPending | submitEventChoice | 显示 pendingEvent，禁止其他行动和学期结算 |
| summary | continueGame | 显示已提交总结，不得再次扣生活费 |
| endingChoice | chooseEnding | 显示第八学期方向条件快照 |
| finished | 查看结果 | 保留最终结果，可保存或重新开始 |

入学填写昵称时 `state = null`，属于界面初始化过程，不是可保存的游戏阶段。新局进入 playing；行动或选项可能进入 eventPending；结算进入 summary。第 1～7 学期继续后进入下一学期并检查事件，第 8 学期继续后进入 endingChoice，确认方向后进入 finished。始终不创建第九学期。

## 4 共享状态与数据字典

### GameState 顶层字段

| 字段 | 类型与约束 | 更新与保留规则 |
| --- | --- | --- |
| version、rulesVersion | number，均为 3 | 规则兼容依据 |
| saveFormatVersion、appVersion | number 为 1；string 为 0.3.0 | 格式兼容与发布定位 |
| nickname | string，去首尾空白后 1～12 个字符 | 控制字符不允许，跨学期保留 |
| background | {id, college, major} | 由种子生成的简化学院专业背景 |
| rng | {algorithm, seed, value, calls} | algorithm 为 mulberry32-v1，保留当前位置 |
| term、phase | term 为 1～8；phase 见第 3 节 | 由规则入口推进 |
| revision、processedCommands | 非负整数；string[] | 对应成功业务操作 |
| time、energy、money | 整数；0～12、0～100、0～1000000 | 新学期 time=12、energy=80；money 保留 |
| social、fitness、mood | 整数，各为 0～100 | 初始 20、50、70，跨学期保留 |
| preparation | 整数，0～100 | 初始 0，下学期清零 |
| furtherStudy、jobPreparation | 整数，各为 0～100 | 深造与求职准备，跨学期保留 |
| counts | {[actionId]: number} | 本学期行动次数，下学期清空 |
| courses、summary | CourseRecord[]；CourseRecord 或 null | 最多八条；总结对应最近一次已提交结算 |
| chains | {project, club, internship} | 三条链的 ChainState，跨学期保留 |
| pendingEvent、eventQueue | EventInstance 或 null；EventInstance[] | 当前待选实例和队列，读档原样恢复 |
| eventFlags、eventHistory | 标记对象；事件处理记录数组 | 防重复及随机抽取标记，不在读档时重置 |
| experiences | 经历对象数组 | type 为 project、club、internship 或 fitnessTest |
| history | 成功操作记录数组 | 含 command、commandId、revision、before、after 等 |
| endingOptions、result | 方向快照或 null；最终结果或 null | 第八学期评估，选择后形成最终结果 |

新局的钱包为 1000 元。表中数值范围同时受 state-validation.js 校验；新增字段或调整范围时，创建、规则变更、校验、存档和测试必须一起修改。

### 关键子结构

`ChainState` 为 `{status, progress, startedTerm, deadline, nextEligibleTerm, reviewAfter}`。status 取 idle、active、deferred、completed、missed；progress 为 0～2 次投入。初始 status=idle、progress=0、nextEligibleTerm=1，其余时间字段为 0。

`EventInstance` 为 `{id, term, instanceId}`。id 引用 EVENTS 的稳定键；instanceId 格式为“链名或 daily:事件 ID:学期”，例如 `project:projectReview:3`。choiceId 只在当前事件内有意义，提交时必须一并绑定实例。

`CourseRecord` 含 term、name、preparation、grade、passed、livingCost、aid、moneyAfter、unusedTime、counts、attributes、notices。结算后 summary 与 courses 最后一条内容一致。成绩是记录中的 grade，不能另外建立可任意修改的成绩属性。

`endingOptions` 含 average、passed、graduated、options；每个选项含 id、title、available、requirements，每项条件保存 label、met、value。`result` 含 direction、title、requirements、average、passed、experiences、courses，用于解释最终方向。

## 5 规则接口契约

### 调用与返回

当前使用 JavaScript 函数接口。浏览器通过 `CampusGame` 调用，Node.js 通过 `require('./game.js')` 获取同一组接口；不引入额外 HTTP 接口或数据库表。

| 接口 | 输入与用途 |
| --- | --- |
| validateNickname(value) | 返回 {ok, value} 或 {ok:false, reason} |
| createGame({nickname, seed}) | 返回初始 GameState；非法输入抛错，由界面捕获 |
| getAction(state, actionId) | 返回带背景加成的配置；未知 ID 返回 null |
| averageGrade(state) | 返回已结算成绩的精确平均值，无记录时为 0 |
| availability(state, actionId) | 只读检查行动条件，返回 {ok, reason} |
| previewChanges(state, effect) | 只读返回各资源和属性的实际增量 |
| executeAction(state, actionId, options) | 提交行动、次数、链条投入并检查事件 |
| eventAvailability(state, choiceId, instanceId) | 只读检查事件阶段、实例、选项和资源 |
| submitEventChoice(state, choiceId, options) | 提交选项、标记和经历，接续事件队列 |
| previewSettlement(state) | 只读返回成绩、生活费、援助、余额和延期说明 |
| endTerm(state, options) | 提交本学期结算，进入 summary |
| continueGame(state, options) | 推进下一学期，或在第八学期后生成方向快照 |
| evaluateEndings(state) | 只读计算平均成绩、达标学期和方向条件 |
| chooseEnding(state, directionId, options) | 确认可用方向，进入 finished |
| validateState(state) | 校验完整状态，返回 {ok} 或 {ok:false, reason} |
| stateBrief(state) | 返回日志用状态摘要 |
| replay({nickname, seed, commands}) | 返回 {ok, state}；失败附步骤和 reason |

成功变更统一返回 `{ok:true, state, changes?, summary?, entry}`；失败返回 `{ok:false, reason, state}`。changes 主要用于行动和事件反馈；其他操作可为空。entry 是本次成功操作日志，summary 可能为 null。调用方不得假定所有成功结果均含有数值变化。

### options 与防重复

| 字段 | 界面提交约定 |
| --- | --- |
| commandId | 每次确认生成唯一非空字符串，最长 128 字符；重复提交拒绝 |
| expectedRevision | 传按钮或面板生成时绑定的 revision；必须等于当前状态版本 |
| eventInstanceId | 提交事件选项时传当时展示的 pendingEvent.instanceId |

当前规则允许测试省略 commandId、expectedRevision，并生成默认编号；正式界面显式传入。过期面板应重新渲染后由玩家重新操作，不要把旧请求的 expectedRevision 偷换成最新值后自动重试。

reason 当前是可展示文本，没有稳定错误码。界面展示原因并刷新可用性，不依赖完整中文句子做业务分支；今后若增加错误码，应同时修改调用方、测试和本文。

## 6 可直接使用的调用示例

### 行动与事件

以下示例使用浏览器全局接口，实际应用继续由 app.js 持有 state 并通过现有 runCommand 提交。每段示例在对应阶段调用。

```javascript
let state = CampusGame.createGame({
  nickname: '对接测试', seed: 'handoff-v1'
});
const action = CampusGame.executeAction(state, 'study', {
  commandId: 'handoff:study:1', expectedRevision: state.revision
});
if (action.ok) state = action.state;
else console.warn(action.reason);
// 成功后：revision=1，time=10，energy=65，
// preparation=20，mood=67；其余初始属性保持。

if (state.phase === 'eventPending') {
  const event = state.pendingEvent;
  // 每个现有事件均提供免费 later 或 abandon 退出路径。
  const choiceId = CampusGame.EVENTS[event.id].choices.find(x =>
    (x.id === 'later' || x.id === 'abandon') &&
    CampusGame.eventAvailability(state, x.id, event.instanceId).ok
  ).id;
  const result = CampusGame.submitEventChoice(state, choiceId, {
    commandId: 'handoff:event:' + state.revision,
    expectedRevision: state.revision,
    eventInstanceId: event.instanceId
  });
  if (result.ok) state = result.state;
}
```

第八学期的成果确认不允许 later 延期，此时应选择合法 complete 或免费 abandon。正式界面为每个选项调用 eventAvailability，并展示对应的禁用原因。

### 结算与继续

```javascript
// 仅在 playing 阶段展示；取消预览不修改状态。
const preview = CampusGame.previewSettlement(state);
// 玩家确认后再调用：
const settled = CampusGame.endTerm(state, {
  commandId: 'handoff:settle:' + state.term,
  expectedRevision: state.revision
});
if (settled.ok) {
  state = settled.state; // summary，先展示总结并尝试自动保存
}
// 玩家点击继续后调用，不能直接修改 state.term：
const next = CampusGame.continueGame(state, {
  commandId: 'handoff:continue:' + state.term,
  expectedRevision: state.revision
});
if (next.ok) state = next.state;
```

previewSettlement 是只读计算函数，不替代阶段校验；提交必须以 endTerm 的结果为准。保存失败时仍展示已完成结算和失败提示，重试保存不再次调用 endTerm。

### 保存与读取

```javascript
// 实际 app.js 已捕获 localStorage 访问异常并允许继续游戏。
const service = CampusSave.createSaveService(window.localStorage);
const saved = service.save(state);
if (!saved.ok) console.warn(saved.reason);
const loaded = service.load('primary'); // 或 'backup'
if (loaded.ok) state = loaded.state;
else console.warn(loaded.reason); // 保留当前内存进度
```

| internshipWork 南门 | 时间2 精力15；钱包100及投入1次 | 已接受实习，总投入最多2次；每学期最多2次 |

申请还受链条状态和 nextEligibleTerm 约束；已完成的链条不能重复申请。工程类 projectWork 额外增加 5 学习进度，经管类 clubWork 额外增加 2 社交，信息类 selfStudy 少耗 3 精力。界面展示成本与收益应调用 getAction，避免自行重复计算背景加成。

config.js 中 time、energy、money 表示消耗，recovery 表示恢复精力，income 表示钱包收入，mood 等属性字段可正可负。表中的心情成本受下限截断，并非额外的行动门槛。休息在精力和心情都已满时禁用；普通学习在学习进度已满时禁用。

## 8 事件链与毕业方向

### 事件配置与调度

| eventId | 触发条件 | priority |
| --- | --- | --- |
| roommateCare | 心情严格低于30，每学期至多一次 | 10 |
| fitnessTest | 偶数学期锻炼后体能至少60，每学期至多一次 | 20 |
| projectOffer、projectReview | 项目申请；两次投入且进入申请之后的学期 | 30、31 |
| clubOffer、clubReview | 秋季招新申请；两次投入且进入加入之后的学期 | 40、41 |
| internshipOffer、internshipReview | 实习申请；完成两次投入且满足 reviewAfter | 50、51 |
| campusDiscussion | 每学期首次自主学习后抽取，概率35% | 60 |

项目、社团和实习关键节点按条件触发。随机数只用于入学背景和图书馆讨论机会；新局背景抽取两次，首次自学的机会每学期只抽取一次。普通行动收益与成绩计算保持确定性。

满足条件的实例去重后，按 priority、instanceId 排序。已有 pendingEvent 时保留当前事件，新事件排入 eventQueue；每次选项成功提交后处理下一实例。读档恢复队列与 eventFlags，不重新抽签，也不补发已领取奖励。

新增事件必须同时明确：稳定 ID、触发位置、实例去重范围、优先级、选项成本与收益、免费退出路径、记录或经历变化。config.js 增加文字并不自动实现触发；触发与链条效果需在 game.js 中接入，并同步校验与测试。

### 链条推进

申请后玩家接受才进入 active，申请成本在申请行动时扣除，接受邀请不重复扣除。累计两次投入后，项目与社团须在后续学期确认；实习可在满足确认时间后立即进入确认事件。

到期未完成时，结算将 deadline 延到下一学期并保留投入；选择“延后确认”会更新 reviewAfter 和 deadline。选择完成将链条标记为 completed，并生成一次对应经历；放弃标记 missed，不生成完成经历。第八学期禁止继续延期，仍有免费放弃路径；结算时未完成链条记为 missed 并写入说明。

### 学期结算与方向条件

成绩固定为 `Math.round(40 + preparation * 0.6)`，60 分及以上为该学期达标。每学期生活费 300 元，援助为 `Math.max(0, 300 - money)`，余额为原钱包加援助减生活费。即使时间、精力和钱包均为 0，也应能够处理免费选项后结算。

| directionId | 展示名称 | 条件 |
| --- | --- | --- |
| ordinary | 普通毕业 | 八条课程记录，平均成绩至少60，至少六学期达标 |
| furtherStudy | 继续深造 | 普通毕业条件，平均至少80，项目completed，深造准备至少60 |
| employment | 进入就业 | 普通毕业条件，实习completed，求职准备至少60 |
| notQualified | 暂未达到毕业条件 | 已完成八学期，但不满足普通毕业条件 |

平均值按八条成绩的精确平均值判定，展示取舍不能改变阈值。满足多个方向时由玩家选择。第八学期 summary 点击继续后生成 endingOptions；chooseEnding 使用该快照确认，结果页展示满足与缺失条件及经历依据。

## 9 存档与兼容对接

### 服务接口与外层结构

`CampusSave.createSaveService(storage, {now?})` 接收实现 getItem、setItem、removeItem 的存储适配器；now 可注入返回 ISO 时间字符串的函数。浏览器使用 localStorage，测试使用内存适配器。

| 接口 | 返回与调用要求 |
| --- | --- |
| inspect() | 返回 ok、primary、backup、temporary；主档与备份各自含校验结果 |
| save(state) | 成功返回 ok、savedAt、saveSequence、warning；失败返回 reason，冲突附 conflict |
| load('primary' 或 'backup') | 成功返回独立候选 state、savedAt、saveSequence；失败保留当前内存 |
| CampusSave.parse(raw) | 校验 JSON 外层、版本、大小、深度与完整状态；空档附 empty |

存档 JSON 外层字段为 saveFormatVersion、rulesVersion、appVersion、saveSequence、savedAt、state；state 为完整 GameState。saveSequence 从 1 开始随成功保存递增；savedAt 为 ISO 时间，界面按北京时间展示。文件总大小上限 1 MiB，结构深度最多 14 层，完整校验由 parse 与 state-validation.js 共同完成。

| 用途 | localStorage 键 |
| --- | --- |
| 主档 | bjtu-life:mvp:main |
| 备份 | bjtu-life:mvp:backup |
| 临时档 | bjtu-life:mvp:temporary |

### 保存与恢复流程

保存按“校验状态 → 检查主档冲突 → 写临时档并回读 → 备份有效主档并回读 → 再检查冲突 → 替换主档并确认 → 清理临时键”执行。备份失败应停止替换主档；清理临时键失败但主档已确认时，返回成功并附 warning。

本地存储多键操作不是原子事务。两次比较主档与 storage 事件提示共同减少标签页覆盖风险；发现冲突时提示先读取最新存档，不自动用当前旧进度覆盖。主档损坏时，由玩家主动选择有效备份；临时档不自动提升为主档。

保存失败保留已成功执行的内存状态；读取失败不替换当前状态。成功读取后按 phase 恢复相应弹窗、事件队列、课程、经历和随机数当前位置，不能只恢复数值栏。

### 自动保存与版本变化

endTerm 成功和 chooseEnding 成功后由界面调用自动保存；其余合法阶段支持手动保存。进入下一学期并不单独触发自动保存，刷新可能回到最近一次已保存的总结或手动节点。

未知规则版本或格式版本明确拒绝加载；同格式、同规则允许 appVersion 标记变化。调整玩法数值、稳定 ID、状态含义或结构时，M1、M3、M4 共同决定规则及格式版本变化，补齐拒绝旧档或迁移方案及测试后再发布。当前没有自动迁移能力，不得只提高 appVersion 就认定存档兼容。

## 10 开发协作与接口变更

### 任务与合并流程

以下为团队执行建议。每项任务先在飞书或任务清单中记录负责人、目标行为、影响模块、验收步骤和依赖，再建立功能分支；建议分支名为 `feat/任务号-功能`、`fix/任务号-问题`、`docs/任务号-文档`。

1. 开始前同步 main，确认共享文件的实际修改人和接口基线。
2. 开发时使用统一入口；涉及新字段或 ID 时先提交数据约定，再接界面与存档。
3. 合并前运行两份自动测试，并执行受影响场景的浏览器验证。
4. PR 描述写明最终行为、修改模块、兼容影响、测试结果与遗留问题；相关模块负责人评审后合并。
5. 主分支集成后更新文档与验收记录，由发布负责人统一发布并记录提交号。

接口变更记录至少包含“原契约、新契约、调用方、存档影响、测试变化、负责人、目标版本”。涉及 game.js 时由 M1 汇总；涉及状态与存档时 M4 必须参与；M5 根据影响范围追加回归。
