# 团队成员如何登录和维护游戏服务器

每位组员使用自己的 SSH 密钥和 Ubuntu 账号。负责人保管阿里云管理账号，通过现有的 root 终端开户。以下以组员 `bjtu-chen` 为例，实际操作时换成该成员的专属账号名。

| 成员职责 | 可执行的操作 | 负责人授予的权限 |
| --- | --- | --- |
| 项目成员 | 登录、查看服务状态、把发布包上传到自己的主目录 | 个人 SSH 账号 |
| 数据分析 | 随时导出并下载玩家存档及结局反馈 | 加入 `bjtu-analysts` |
| 值班运维 | 查看状态、重启游戏后端 | 加入 `bjtu-ops` |
| 发布负责人 | 切换正式版本、修改 Nginx、配置密钥、管理组员 | 系统管理员 |

## 1. 组员在自己的 Windows 电脑生成密钥

在 PowerShell 执行以下命令，为私钥设置口令。已为项目生成密钥的成员可直接使用现有公钥。

```powershell
ssh-keygen -t ed25519 -f "$env:USERPROFILE\.ssh\bjtu_team_ed25519"
Get-Content "$env:USERPROFILE\.ssh\bjtu_team_ed25519.pub"
```

将以 `ssh-ed25519` 开头的整行公钥发给负责人。私钥文件 `bjtu_team_ed25519` 留在成员自己的电脑上。

## 2. 负责人开户，组员首次登录

负责人在服务器的 **root 终端**为新成员执行以下命令。出现「粘贴公钥」时，把组员发来的整行内容粘贴进去。

```bash
member=bjtu-chen
adduser --disabled-password --gecos '' "$member"
read -r -p '粘贴公钥并回车：' pubkey
printf '%s\n' "$pubkey" | ssh-keygen -lf - &&
printf '%s\n' "$pubkey" | sudo -H -u "$member" sh -c '
  set -eu
  umask 077
  cd "$HOME"
  mkdir -p .ssh
  IFS= read -r key
  grep -Fxq -- "$key" .ssh/authorized_keys 2>/dev/null || printf "%s\n" "$key" >> .ssh/authorized_keys
'
ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub
```

负责人把账号名、公网地址和最后一行的服务器 SHA256 指纹发给组员。组员在自己的 PowerShell 中登录，首次连接时核对指纹，一致后输入 `yes`。如果连接超时，负责人在阿里云安全组中核对该成员公网 IP 对 TCP 22 的入方向访问。

```powershell
ssh -i "$env:USERPROFILE\.ssh\bjtu_team_ed25519" -o HostKeyAlgorithms=ssh-ed25519 bjtu-chen@服务器公网地址
```

登录后运行 `whoami` 查看个人账号，运行 `systemctl is-active nginx bjtu-npc` 查看网站和后端状态。

## 3. 负责人一次性配置团队权限

在 root 终端创建角色组。下面的导出命令以游戏服务账号读取正式数据库 `/var/lib/bjtu-npc/playthroughs.sqlite`，输出两份 JSONL 打成的压缩包。临时导出目录仅服务账号可读。

```bash
groupadd -f bjtu-analysts
groupadd -f bjtu-ops
cat > /usr/local/sbin/bjtu-export-playthroughs <<'SH'
#!/bin/sh
set -eu
[ "$#" -eq 0 ] || exit 2
umask 077
out=$(/opt/bjtu-npc/current/node /opt/bjtu-npc/current/scripts/playthrough-store.js export /var/lib/bjtu-npc/playthroughs.sqlite /tmp)
trap 'rm -f -- "$out/game_saves.jsonl" "$out/game_feedback.jsonl"; rmdir -- "$out"' EXIT
/usr/bin/tar -C "$out" -czf - game_saves.jsonl game_feedback.jsonl
SH
chown root:root /usr/local/sbin/bjtu-export-playthroughs
chmod 0755 /usr/local/sbin/bjtu-export-playthroughs
visudo -f /etc/sudoers.d/bjtu-game-team
```

在打开的编辑器中写入下列两行并保存。分析组只获准按固定命令导出，值班组只获准重启指定服务。

```sudoers
%bjtu-analysts ALL=(bjtu-npc) NOPASSWD: /usr/local/sbin/bjtu-export-playthroughs ""
%bjtu-ops ALL=(root) NOPASSWD: /usr/bin/systemctl restart bjtu-npc.service
```

保存后运行 `visudo -c`。检查通过后，按成员实际分工执行相应的一行。兼任两种职责的成员可加入两个组。

```bash
usermod -aG bjtu-analysts bjtu-chen
usermod -aG bjtu-ops bjtu-chen
```

组员退出并重新登录，执行 `id -nG` 和 `sudo -l` 核对已生效的权限。

## 4. 分析人员自己下载数据

分析人员用自己的账号登录服务器，在 **服务器终端**运行以下命令。成功后会列出两个文件并打印压缩包的绝对路径。游戏可以在导出期间继续运行。

```bash
umask 077
archive=$(mktemp --suffix=.tar.gz "$HOME/bjtu-analysis-XXXXXXXX")
if sudo -n -u bjtu-npc /usr/local/sbin/bjtu-export-playthroughs > "$archive"; then
  tar -tzf "$archive" && printf '下载路径 %s\n' "$archive"
else
  rm -f -- "$archive"
fi
```

在 **自己电脑的 PowerShell** 中打开用于本次分析的文件夹，把远端路径换成刚才打印的值。

```powershell
scp -i "$env:USERPROFILE\.ssh\bjtu_team_ed25519" bjtu-chen@服务器公网地址:/home/bjtu-chen/bjtu-analysis-实际后缀.tar.gz ./bjtu-analysis.tar.gz
tar -xzf ./bjtu-analysis.tar.gz
```

`game_saves.jsonl` 保存每次存档与结局，`game_feedback.jsonl` 保存自愿填写的建议。按 `run_id` 汇总一局的过程，按 `run_id` 和 `snapshot_id` 将反馈对应到具体结局。导出含玩家昵称和人物对话，请保存在团队受控目录中。Excel 导入和关联步骤见[游玩数据与反馈导出](游玩数据与反馈导出.md)。

## 5. 值班、发布与撤权

- **值班运维**在确认需要重启时执行 `sudo /usr/bin/systemctl restart bjtu-npc.service`，再用 `systemctl is-active bjtu-npc nginx` 检查两个服务。重启期间在线请求可能需要重试。
- **发布新版**时，组员用个人账号将发布包上传到自己的主目录，并将包名与校验值交给发布负责人。负责人按部署流程核对包、切换正式版本和验证公网。[服务器部署说明](DeepSeek对话接入说明.md)
- **交接发布管理权**时，若成员需要完整的系统管理权限，负责人在 root 终端运行 `passwd bjtu-chen` 为该个人账号设置初始口令，再运行 `usermod -aG sudo bjtu-chen`。这会授予整台服务器的管理员权限。新负责人用自己的 SSH 密钥重新登录，用 `passwd` 更换初始口令，再用 `sudo -v` 验证。
- **调整分工**时，负责人用 `gpasswd -d bjtu-chen 组名` 移除已授予的角色，组名取 `bjtu-analysts`、`bjtu-ops` 或 `sudo`。成员离组时，负责人在 root 终端执行 `usermod --expiredate 1970-01-02 bjtu-chen` 停用该账号。确认该成员已完成手头操作后，用 `loginctl terminate-user bjtu-chen` 结束其现有会话。
