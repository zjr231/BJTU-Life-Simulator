# M4 静态发布与恢复说明

本文用于把当前纯前端项目发布到固定 HTTPS 地址，并验证存档可继续使用。当前三栏位候选基于 c005479；实际发布提交号、时间和线上验收结果由发布人执行后填写。本次本地交付没有发布到线上。最新存档界面与接口见 [三栏位说明](M4三栏位存档说明.md)。

## 发布前条件

1. 团队确认目标仓库为 zjr231/BJTU-Life-Simulator，并由有权限的成员执行合并、推送和 Pages 配置。当前对接文档指定 GitHub Pages 使用 main 分支根目录；发布前到仓库 Settings → Pages 核实实际设置。
2. M1、M3 确认本轮状态及规则兼容，M2 确认保存/恢复界面，M5 汇总影响范围和回归结果。本次规则仍为 3、存档格式仍为 1。
3. 补齐已有地图素材的来源、授权资料及已知问题。素材出处不能从现有图片内容推断。
4. 运行以下检查并保存完整输出：

```text
node --test
node scripts/check-release.js
```

## 发布文件

必须发布 index.html、styles.css、config.js、rng.js、state-validation.js、game.js、save.js、audio.js、app.js、assets/campus-map-reference.png 和 .nojekyll。保留资源的原路径与大小写，浏览器脚本顺序固定为 config、rng、state-validation、game、save、audio、app。

无需 npm 安装、打包、数据库或服务器端应用。Node.js 24 用于本地与工作流测试，Python 静态服务仅用于本地访问。不要把本地 HTTP 地址视为正式站点。

## GitHub Pages 操作

1. 将审核后的 M4 变更合入团队统一基线，确认合并结果包含共享文件的最新版本。
2. 查看 M4 save and static release checks 的运行结果，确认测试和静态资源检查均通过。此工作流只做检查，不修改部署配置，也不自动阻止现有 Pages 发布；团队如需强制检查，应由管理员配置分支保护或合并规则。
3. 由发布负责人按团队流程推送目标 main 分支。确认 Pages 来源为该分支的根目录，等待 pages build and deployment 成功。
4. 记录发布的完整提交号和北京时间，并从正式地址核对资源。对接文档指定地址为 https://zjr231.github.io/BJTU-Life-Simulator/ 。可执行：

```text
node scripts/check-release.js --url https://zjr231.github.io/BJTU-Life-Simulator/
```

线上检查会把公开运行文件与当前本地文件逐字节比较；应在对应发布提交的工作区执行。失败时检查部署是否尚未完成、是否访问了错误地址或缓存是否尚未更新。.nojekyll 只做本地存在性检查，不要求对外提供下载。

5. 资源检查通过后，仍须完成以下浏览器验收并记录证据；构建成功和文件一致不代表用户流程已通过。

## 浏览器验收步骤

以下项目本次均待执行。每项记录地址、提交号、程序/规则/格式版本、浏览器及设备版本、结果、截图或复现日志。

| 编号 | 操作 | 通过条件 |
| --- | --- | --- |
| JT09-1 | 新局填写昵称，完成课程学习，选择栏位 2 保存、刷新、从栏位 2 继续 | 昵称、学期、学习进度、资源及历史一致；栏位 1、3 不被改写 |
| JT09-2 | 申请社团后停在百团大战，保存、刷新、继续主档、接受 | 恢复同一待选实例，不重复扣申请费 |
| JT09-3 | 结束学期，在总结页刷新并继续主档 | 回到同一总结，不重复扣生活费；继续后只进入下一学期一次 |
| JT09-4 | 玩到第八学期，方向选择页手动保存并刷新 | 恢复选项与条件快照；选择后自动保存，刷新恢复最终结果，无第九学期 |
| JT10-1 | 同一地址开 A/B 两页；均读取栏位 2；A 学习并保存到栏位 2，B 再保存到栏位 2；再检查分别保存不同栏位 | 同栏位 B 显示冲突，A 主档不被覆盖；不同栏位互不影响 |
| JT10-2 | 隔离测试浏览器内先保存两次；将主档改为损坏 JSON，刷新后主动恢复备份 | 不自动采用临时档；备份可恢复；再次保存后仍有有效备份 |
| JT10-3 | 隔离测试浏览器中将存档规则或格式版本设为未知值 | 明确拒绝旧档，当前内存不被替换 |
| JT10-4 | 测试浏览器禁用站点本地存储；新局、行动、尝试保存与结算 | 说明保存失败，已执行的内存进度可继续，不重新结算或扣费 |
| JT10-5 | 用隔离测试配置模拟空间不足、备份写失败和主档确认冲突 | 内存保留；备份失败时不替换主档；冲突不尝试回滚他人写入 |
| JT12 | 正式 HTTPS 地址逐项重跑新局、行动、保存、刷新恢复、结算、自动保存 | 版本、资源及实际交互符合当前发布提交 |

损坏、版本和空间不足测试只使用隔离测试浏览器的数据，不覆盖真实玩家存档。自动故障注入覆盖见 save.test.js、mvp.test.js；浏览器实际失败表现仍需单独记录。

至少执行 Chrome、Edge 和实际手机浏览器。390 像素桌面视口可辅助检查弹窗可达性，但不能代替手机真机结果。普通模式不展示内部调试字段；?debug=1 可核对阶段、revision 和导出复现日志。

## 回退与存档

发布后发现阻断问题时，由发布人基于已验证提交创建回退提交，再按相同流程部署并复测。不得用强制推送覆盖团队历史。回退前共同检查规则与存档格式；代码回退不会还原玩家的 localStorage。

本轮兼容同规则、同格式旧档。若以后变化影响状态含义，发布前必须明确拒绝旧档或实施迁移，不仅提高 appVersion。更换协议、域名、端口或浏览器会进入独立存储空间，旧地址的档案不会自动随站点迁移。
